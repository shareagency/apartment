# 📋 ПОШАГОВАЯ ИНСТРУКЦИЯ ПО ДЕПЛОЮ (HOWTO)

Данный документ содержит подробные объяснения на русском языке как запустить, собрать и деплоить лендинг-страницу квартиры для аренды на GitHub Pages.

---

## 🔧 1. ИНИЦИАЛИЗАЦИЯ ПРОЕКТА

### Шаг 1: Создание директории проекта

```bash
# Создайте директорию проекта
mkdir apartment-landing-page
cd apartment-landing-page
```

**Что это делает:** Создает новую папку для проекта и переходит в неё.

---

### Шаг 2: Инициализация Vite с React + TypeScript

```bash
# Инициализация Vite с шаблоном React+TypeScript
npm create vite@latest . -- --template react-ts

# Установка зависимостей
make install
```

**Что это делает:** 
- Создает базовую структуру проекта Vite с React и TypeScript
- Устанавливает все необходимые зависимости из `package.json`

---

### Шаг 3: Установка Tailwind CSS и Shadcn UI

```bash
# Установка Tailwind CSS
npm install -D tailwindcss postcss autoprefixer
npx tailwindcss init -p

# Инициализация конфигурации Tailwind в tailwind.config.js
# В файле tailwind.config.js добавьте:
# content: [
#   "./src/**/*.{js,ts,jsx,tsx}",
# ],
```

**Что это делает:**
- Устанавливает Tailwind CSS для стилей
- Создает конфигурационные файлы PostCSS
- Настраивает содержимое для сканирования файлов

---

### Шаг 4: Установка Shadcn UI (опционально)

```bash
# Установка Shadcn UI
npx shadcn-ui@latest init
```

**Что это делает:** 
- Добавляет компоненты Shadcn/UI в проект
- Создает необходимую конфигурацию

---

### Шаг 5: Создание структуры папок

```bash
mkdir -p src/components src/public/images description doc
mkdir -p .github/workflows
```

**Что это делает:** Создает папки для компонентов, статических файлов и GitHub Actions.

---

## 🖼️ 6. ДОБАВЛЕНИЕ КОРТАНТИ И КОНТЕНТА

### Шаг 6: Помещение изображений квартиры

Создайте изображения в `public/images/`:

```bash
# Создайте папку для изображений
mkdir -p public/images

# Поместите файлы 1.jpg, 2.jpg (или используйте placeholder-файлы)
# В проекте уже есть: public/images/1.jpg и public/images/2.jpg
```

**Важно:** Изображения должны лежать в папке `public/images/` с именами `1.jpg`, `2.jpg`, ...

---

### Шаг 7: Создание текстового описания

```bash
# Создайте текстовое описание квартиры
mkdir -p description
echo "Описание квартиры..." > ./description/text.txt
```

**Где разместить:** Файл `description/text.txt` должен содержать полное описание квартиры.

---

### Шаг 8: Добавление PDF договора

```bash
# Добавьте файл договора
mkdir -p doc
cp your_contract.pdf ./doc/doc.pdf
```

**Важно:** Файл договора должен называться `doc.pdf` и лежать в папке `doc/`.

## 🚀 10. КОМАНДЫ РАЗРАБОТЧИКА (Makefile)

### Доступные команды Makefile:

| Команда | Описание | Когда использовать |
|---------|----------|-------------------|
| `make install` | Установка всех зависимостей | Первый запуск проекта |
| `make build` | Сборка проекта в папку dist/ | Перед деплоем на GitHub Pages |
| `make preview` | Локальный сервер разработки | Проверка работы сайта локально |
| `make clean` | Очистка временных файлов | После разработки, перед сборкой |
| `make deploy` | Предварительный деплой через CI/CD | После изменений в коде |

## 📦 11. ДЕПЛОЙ НА GITHUB PAGES

### Шаг 1: Создание репозитория GitHub

1. Залитайте код в новый репозиторий GitHub (например: `apartment-landing`)
2. Убедитесь, что ветка называется `main`

---

### Шаг 2: Настройка GitHub Pages в репозитории

1. Откройте ваш репозиторий на GitHub
2. Перейдите в **Settings** → **Pages** (в меню слева)
3. В разделе **"Deploy from a branch"**:
   - Выберите ветку: `main`
   - Путь: `/` (корень)
4. Нажмите **Save**

---

### Шаг 3: Сборка и деплой через GitHub Actions

Когда вы делаете `git push origin main`:

1. GitHub автоматически запускает **GitHub Actions** workflow из файла `.github/workflows/deploy.yml`
2. Workflow собирает проект в папку `dist/`
3. GitHub Pages разворачивает этот код на ваш домен

---

### Шаг 4: Проверка деплоя

После завершения сборки (обычно 1-3 минуты):

1. Откройте URL страницы GitHub Pages: `https://ВАШ_ПОЛЬЗОВАТЕЛЬ.github.io/apartment-landing/`
2. Проверьте корректность отображения на всех экранах:
   - Мобильные устройства (360px × 800px)
   - Ноутбуки (1366px × 768px)
   - Десктоп Full HD (1920px × 1080px)

## 🔄 12. ОТКАТ ГИТ РЕПОЗИТОРИЯ (Rollback)

### Команда отката на одну версию вниз:

```bash
make rollback-down-safe
```

**Что делает:** Безопасный откат последней версии без потери истории.

---

### Команда отката на одну версию вверх:

```bash
make rollback-up-safe
```

**Что делает:** Переход к следующей версии HEAD+1 (требует fetch最新 commits).

---

### Проверка последних коммитов:

```bash
git log --oneline -5
```

**Показывает:** Последние 5 коммитов в истории репозитория.

## 🔍 14. УСТРАНЕНИЕ ПРОБЛЕМ

### Проблема: Сборка не проходит

```bash
# Проверьте ошибки TypeScript
npx tsc --noEmit

# Проверьте вывод сборки
npm run build
```

**Решение:** Исправьте ошибки в коде согласно сообщению об ошибке.

---

### Проблема: Изображения не отображаются

1. Убедитесь, что файлы лежат в `public/images/`
2. Имена файлов должны быть: `1.jpg`, `2.jpg` и т.д.
3. Проверьте пути в коде на соответствие `/images/*.jpg`

---

### Проблема: PDF не открывается

1. Убедитесь, что файл называется `doc/doc.pdf`
2. Проверьте права доступа к файлу
